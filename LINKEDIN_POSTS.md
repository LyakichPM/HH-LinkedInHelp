## ВАРИАНТ 1: «Технический кейс» (для девов/техлидов)
**Хук:** Как обойти защиту hh.ru и не сойти с ума

---

За 3 недели написал бота, который обходит новый Magritte UI на hh.ru, нормализует `\\xa0` в русском тексте и отправляет кастомные сопроводительные вместе с откликом — не отдельно.

**Репозиторий:** https://github.com/LyakichPM/HH-LinkedInHelp

### Что внутри:
- **Playwright + Chromium** — единственный способ пробить hh.ru из-за РФ (системный python в sandbox, exit code 49)
- **Magritte selectors** — `data-qa` атрибуты вместо хрупких CSS
- **Toggle trap** — кнопка «Добавить сопроводительное» создаёт *новый* `textarea`, а не показывает старый. Решение: дельта по индексам до/после клика
- **Неразрывный пробел** — «Вы\\xa0откликнулись» ломает поиск по тексту. Фикс: `.replace('\\xa0', ' ')` на уровне `body.innerText`
- **Auto-save на blur** — письмо сохраняется только после потери фокуса. Нужно: `Tab` → `wait 7s` → `reload` → verify
- **Telegram curl workaround** — PowerShell 5.1 ломает кириллицу в `Invoke-RestMethod`. Решение: UTF-8 JSON файл + `curl.exe -d "@file"`

### Жёсткое правило в коде:
```python
# НИКОГДА не отправляем пустой отклик
assert cover_letter_text.strip(), "Empty cover letter not allowed"
verify_cover_saved(page, vacancy_id)  # reload + check
```

### Стек:
`Python 3.10+` `Playwright` `requests` `pyyaml` `python-dotenv`

### CLI команды:
```bash
hh search "iGaming PM" 300000 7
hh apply 134646797
hh verify 134646797
hh negotiations
hh cv-design split
hh tg "report ready"
```

---

**Почему открыл:** устал видеть «откликаюсь на всё подряд» без письма. Этот инструмент заставляет писать кастом под каждую вакансию — и проверяет, что письмо реально прилетело.

## ВАРИАНТ 2: «Продуктовый кейс» (для PM/PO/HR)
**Хук:** Как PM сделал себе ATS-бота и перестал терять отклики

---

Раньше: ищу вакансию → копирую шаблон → меняю компанию → забываю прикрепить → отправляю пустой отклик → рекрутер видит «без сопроводительного» → скипает.

Теперь: `/hh-search "iGaming PM" 300000 7` → бот парсит 300+ вакансий → скорчит по матрице (стек/домен/уровень/зарплата) → выдаёт топ-10 → `/hh-apply 134646797` → генерит письмо под стек/домен/уровень → отправляет СРАЗУ с откликом → верифицирует через reload → шлёт отчёт в Telegram.

**Результат за неделю:**
- 8 откликов на iGaming PM вакансии
- 8 кастомных сопроводительных (SQL/ClickHouse, Python, Tableau, A/B tests, retention/LTV)
- 0 пустых откликов
- 6 чатов на chatik.hh.ru с флагом COVER ✅

**Репозиторий:** https://github.com/LyakichPM/HH-LinkedInHelp

### Что бот делает за меня (product thinking):
1. **Discovery** — поиск + фильтры (только с контактами, без тестовых, remote)
2. **Prioritization** — scoring matrix: domain match × tech stack × seniority × salary
3. **Execution** — apply + cover letter в одной транзакции (atomic)
4. **Verification** — reload страницы, проверка DOM, не «успех API», а реальный UI
5. **Feedback loop** — Telegram inbox → читаю команды → запускаю батчи
6. **Fallback** — если кнопка «Прикрепить» сломана (hh.ru багует) → пишу письмо в чат напрямую

### Архитектура мышления:
> «Не автоматизируй хаос. Сначала наведи порядок в процессе, потом пиши код.»

Именно так: сначала — жёсткое правило «нет пустых откликов», потом — код, который это правило гарантирует.

---

**Для кого полезно:**
- PM/PO в поиске — не терять время на рутину
- Рекрутеры — получать релевантные письма, а не спам
- Девы — пример Playwright + Telegram bot + CLI tool

## ВАРИАНТ 3: «История провалов и исправлений» (виральный, живой)
**Хук:** 10 ошибок за неделю, которые научили меня писать надёжный код

---

На прошлой неделе мой бот:
1. Отправил **3 пустых отклика** на старте (забыл прикрепить письмо)
2. Сказал «всё отправилось» — а письма не сохранились (нет reload verification)
3. Сломал селекторы на новом Magritte UI hh.ru (Chat кнопка осталась в DOM)
4. Провал с `\\xa0` — «Вы откликнулись» не находилось в теле страницы
5. Отправил 6 дублей в Telegram (6 мониторов = 409 Conflict)
6. PowerShell съел кириллицу в `Invoke-RestMethod` (curl.exe спас)
7. Системный `python` вернул exit code 49 (песочница) — только `pw_env` работает
8. Toggle «Добавить сопроводительное» создал *второй* textarea — старый пустой
9. Chat fallback проверял сайдбар, не чат — ложные позитивы
10. Не проверял inbox перед запуском — пропустил команды пользователя

**Каждая ошибка → тест / проверка / жёсткое правило в коде.**

Теперь в репозитории:
- ✅ `assert cover_letter, "Empty cover letter not allowed"`
- ✅ `reload_and_verify(page)` после каждого submit
- ✅ `_normalize_body(page)` — убирает `\\xa0` везде
- ✅ Дельта текстовых полей при клике toggle
- ✅ Один монитор, long-poll, inbox JSONL
- ✅ `curl.exe` для Telegram API
- ✅ Chat fallback → конкретный URL чата, не сайдбар

**Репозиторий:** https://github.com/LyakichPM/HH-LinkedInHelp

### Главный урок:
> Автоматизация без верификации = генератор багов в продакшн.
> Автоматизация с верификацией = надежный пайплайн.
