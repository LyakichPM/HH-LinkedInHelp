# hh-agent — инструкция для ИИ-агента

Ты используешь набор Python-инструментов для работы с hh.ru.
Ниже — правила и порядок действий.

## 0. КРИТИЧЕСКИЕ ПРАВИЛА (нарушения уже случались — не повторять)

1. **НИКОГДА не открывай `hh.ru/applicant/vacancy_response?vacancyId=<vid>` для проверки статуса.**
   Это WRITE-эндпоинт: для вакансий без анкетных вопросов сама загрузка страницы
   АВТООТПРАВЛЯЕТ пустой отклик. Инцидент 2026-07-12: ~10 пустых откликов из-за
   «проверки» этим URL. Статус проверяй только read-only способами:
   `hh verify <vid>` (страница `/vacancy/<vid>`), `hh negotiations`, или чат
   (`hh.ru/chat/<chatId>`).

2. **Каждый отклик — только с сопроводительным письмом.** Пустой отклик = провал.
   После отклика ОБЯЗАТЕЛЬНО проверь, что письмо реально в чате работодателя:
   первый пузырь `[data-qa^="chatik-chat-message-"][data-qa$="-text"]` должен
   содержать текст письма, а не «Без сопроводительного письма».
   Флаги результата `apply_to_vacancy()` врут в обе стороны (см. докстринг
   `hh/hh_apply.py`). Если письмо не дошло до чата — дошли его сообщением
   через `hh.ru/chat/<chatId>` (textarea `[data-qa="chatik-new-message-text"]`).

3. **Гейт согласования: сначала список — потом отклики.**
   Найденные вакансии сначала отправь пользователю (в Telegram) списком со
   ссылками. Откликайся ТОЛЬКО на те, которые пользователь явно назвал.
   Никогда не откликайся по своей инициативе и не гоняй apply циклом по списку.

4. **Флаг `applied` из `hh search` НЕНАДЁЖЕН** (наблюдалось `true` у всех
   кандидатов подряд). Реальная проверка «уже откликался?» — по чатам или
   `hh negotiations`, не по этому флагу.

5. **Запускай скрипты из корня репозитория** (`cd` в папку hh-agent).
   Пути к `hh_cookies.json` / `tg_inbox.jsonl` теперь якорятся к корню репо
   кодом (`hh/config.py: resolve_path`), но сторонние скрипты и старые версии
   зависят от cwd: при чужом cwd cookies тихо не загружались, браузер работал
   гостем, и это выглядело как «сессия истекла» (ложная тревога 2026-07-12).
   Если видишь редирект на `/account/login` — сначала проверь cwd/cookies,
   потом уже проси пользователя перелогиниться.

## 1. Авторизация

Перед любыми действиями с hh.ru проверь cookies:
```
hh auth status
```
Если нет — запусти `hh auth login`. Откроется браузер, пользователь логинится вручную.

Файл cookies: `hh_cookies.json` (в .gitignore, не коммитится).

## 2. Поиск вакансий

```
hh search --query "Python Developer" --salary 150000 --period 14 --max-pages 2
```

Флаги:
- `--json` — вывод в JSON для программной обработки
- `--headless` — без графического интерфейса (на сервере)

Поля результата: `vid`, `title`, `employer`, `salary`, `link`, `applied`.

## 3. Проверка статуса

Перед откликом **всегда** проверяй, не откликался ли уже:
```
hh verify <vid>
```

`hh verify` ходит только на read-only страницу `/vacancy/<vid>` — безопасно.
Массовая проверка: `hh negotiations --json` или скан чатов. НЕ полагайся на
`applied` из `hh search` (правило 0.4) и НЕ открывай `vacancy_response`
(правило 0.1).

## 4. Отклик с сопроводительным

**ВАЖНО**: сопроводительное отправляется вместе с откликом, а не после.

```
hh apply <vid> --letter cover_letter.txt [--headless]
```

После `hh apply` обязательно верифицируй письмо в чате работодателя
(правило 0.2) — возвращаемые флаги ненадёжны:
- Вакансия С вопросами: письмо доходит до чата, но readback часто даёт
  ложный отказ «Letter not persisted after submit».
- Вакансия БЕЗ вопросов: сохранение письма на карточке отклика НЕ доносит
  его до чата — чат остаётся «Без сопроводительного письма». Лечится
  отправкой письма сообщением в `hh.ru/chat/<chatId>`.

Формат сопроводительного:
- Приветствие, представление
- Почему эта вакансия и компания
- Ключевой опыт (2-3 предложения)
- Чем можешь быть полезен
- Подпись

## 5. Telegram

Отправка сообщения:
```
hh tg send "Текст сообщения"
```

Чтение входящих (от пользователя через Telegram):
```
hh tg inbox [--clear]
```

Проверка непрочитанных:
```
hh tg count
```

## 6. Проверка откликов / переговоры

```
hh negotiations [--json]
```

Показывает статус активных переговоров.

## 7. Порядок работы при запросе "найди и откликнись"

1. `hh search --json` — найти свежие вакансии
2. Для каждой проверить дубли через `hh verify <vid>` / `hh negotiations`
   (НЕ через флаг `applied` из поиска — он ненадёжен)
3. Показать пользователю список новых вакансий на утверждение и ЖДАТЬ ответа
4. После утверждения: откликаться ТОЛЬКО на явно названные пользователем
   вакансии — подготовить сопроводительные и `hh apply <vid> --letter ...`
5. Верифицировать письмо в чате по каждому отклику (правило 0.2)
6. Отправить финальный отчёт одним сообщением в Telegram

## 8. Cover Letter Generator

Пиши сопроводительные в стиле:
- Кратко и по делу
- Фокус на релевантном опыте (Product Manager, iGaming, Web3)
- Цифры и результаты где возможно
- Без лести и общих фраз

Структура:
- Тема / Заголовок вакансии
- Приветствие
- Кто я (1 предложение)
- Почему подхожу (2-3 предложения с фактами)
- Чем могу быть полезен (1 предложение)
- Подпись

## 9. CV Design Pipeline

Для генерации CV в PDF:
1. Брать HTML шаблон из `cv_designs/`
2. Заполнять данными кандидата
3. Открывать в Playwright (headless)
4. Экспортировать в PDF
5. Отправлять через Telegram

## 10. Telegram bridge

Долгоживущий процесс `tg_bot.py` слушает входящие сообщения
и пишет их в `tg_inbox.jsonl`. Агент читает этот файл командой `hh tg inbox`.

## 11. Безопасность

- `config.local.json` — в .gitignore (токены, прокси)
- `hh_cookies.json` — в .gitignore (сессия hh.ru)
- `tg_inbox.jsonl` — в .gitignore (переписка)
- В публичный репозиторий идёт только код без секретов
- При первом запуске: `hh setup` проверяет всё необходимое
