# hh-agent — инструкция для ИИ-агента

Ты используешь набор Python-инструментов для работы с hh.ru.
Ниже — правила и порядок действий.

## 0. КРИТИЧЕСКИЕ ПРАВИЛА (нарушения уже случались — не повторять)

1. **НИКОГДА не открывай `hh.ru/applicant/vacancy_response?vacancyId=<vid>` для проверки статуса.**
   Это WRITE-эндпоинт: для вакансий без анкетных вопросов сама загрузка страницы
   АВТООТПРАВЛЯЕТ пустой отклик. Инцидент 2026-07-12: ~10 пустых откликов из-за
   «проверки» этим URL. Статус проверяй только read-only способами:
   `hh verify <vid>` (страница `/vacancy/<vid>`), `hh negotiations`, или чат
   (`hh.ru/chat/<chatId>`).

2. **Каждый отклик — только с сопроводительным письмом.** Пустой отклик = провал.
   После отклика ОБЯЗАТЕЛЬНО проверь, что письмо реально в чате работодателя:
   первый пузырь `[data-qa^="chatik-chat-message-"][data-qa$="-text"]` должен
   содержать текст письма, а не «Без сопроводительного письма».
   Флаги результата `apply_to_vacancy()` врут в обе стороны (см. докстринг
   `hh/hh_apply.py`). Если письмо не дошло до чата — дошли его сообщением
   через `hh.ru/chat/<chatId>` (textarea `[data-qa="chatik-new-message-text"]`).

3. **Гейт согласования: сначала список — потом отклики.**
   Найденные вакансии сначала отправь пользователю (в Telegram) списком со
   ссылками. Откликайся ТОЛЬКО на те, которые пользователь явно назвал.
   Никогда не откликайся по своей инициативе и не гоняй apply циклом по списку.

4. **Флаг `applied` из `hh search` НЕНАДЁЖЕН** (наблюдалось `true` у всех
   кандидатов подряд). Реальная проверка «уже откликался?» — по чатам или
   `hh negotiations`, не по этому флагу.

5. **Сопоставление чат ↔ вакансия — ТОЛЬКО по ссылке в шапке чата.**
   Единственный авторитетный источник: `[data-qa="chatik-header-vacancy-link"]`
   (href = `/vacancy/<vid>`) на полной странице `hh.ru/chat/<cid>`.
   НИКОГДА не сопоставляй по regex `/vacancy/<vid>` в `page.content()` —
   левый сайдбар содержит ссылки и превью ВСЕХ остальных чатов, сопоставление
   съезжает. Инцидент 2026-07-13: 8 из 9 чатов сопоставились неверно, письма
   ушли в чужие чаты. Проверяй шапку КАЖДОГО чата ДО отправки. Кнопка
   «Добавить сопроводительное» в чате прикрепляет текст к самому пузырю
   отклика — тем более сверяй шапку перед её нажатием.
   Если что-то ушло не туда — НЕ исправляй сам: любые сообщения работодателю
   (включая извинения/корректировки) только после явного ок пользователя.
   Дай ему ссылку на чат + готовый текст — удалить/отредактировать своё
   сообщение он может вручную через UI (автоматизации этот контрол недоступен).

6. **Запускай скрипты из корня репозитория** (`cd` в папку hh-agent).
   Пути к `hh_cookies.json` / `tg_inbox.jsonl` теперь якорятся к корню репо
   кодом (`hh/config.py: resolve_path`), но сторонние скрипты и старые версии
   зависят от cwd: при чужом cwd cookies тихо не загружались, браузер работал
   гостем, и это выглядело как «сессия истекла» (ложная тревога 2026-07-12).
   Если видишь редирект на `/account/login` — сначала проверь cwd/cookies,
   потом уже проси пользователя перелогиниться.

7. **LinkedIn (`li-tools/`) — никогда не использовать плавающий док.**
   Все отправки/ответы — только через полную страницу `/messaging/`.
   Плавающий док внизу экрана пронизан shadow DOM и может тихо переиспользовать
   уже открытую чужую панель вместо новой (инцидент 2026-07-13 — сообщение
   ушло не в тот диалог). Перед вводом текста ОБЯЗАТЕЛЬНО проверяй, что
   заголовок открытой панели/треда содержит имя ожидаемого адресата
   (`expect_name`/`expect_token` во всех `li_*.py`) — если панель не открылась
   ровно одна, или заголовок не совпадает — abort, не гадай.

## 0-бис. ПРАВИЛА ИЛЬИ п.1–п.10 (он ссылается на них по номерам)

> файл фотографии) в этом файле не хранятся: репозиторий публичный. Они лежат
> в `agent/owner.local.md`, который в `.gitignore`. Плейсхолдеры `<ФИО>`,
> `<телефон>`, `<телеграм>` ниже подставляются оттуда.

Накоплены 08.08–02.09.2026. До 02.09 жили только в контексте сессии и терялись
при её перезапуске. Отдельного `rules.md` нет и заводить не надо — источник один,
этот раздел.

1. **Откликаться только на вакансии, которые Илья назвал явно.** Инициативных
   откликов не бывает (то же, что правило 0.3).
2. **Отклика без сопроводительного письма не бывает.**
3. **Судья доставки один — пузырь в чате работодателя.** Рапорт скрипта,
   вердикт `hh apply` и отметка на карточке судьями не являются.
4. **Фотография обязательна на КАЖДОМ резюме** (путь - в `owner.local.md`).
   Сборка жёстко выходит, если в готовом HTML нет `class="photo"`.
5. **Зарплатные ожидания не пишутся нигде** — ни в письме, ни в анкете, ни в
   чате. Обязательный ответ на вопрос о деньгах: «Готов обсудить на
   собеседовании.» Устный ориентир у Ильи есть, в переписку он не идёт.
6. **Уверенная переформулировка — да, выдумка — никогда.** Запрещены обороты
   признания пробела: «нет опыта», «не умею», «не строил», «не вёл»,
   `I have no ...`, `I do not have ...`. Чего за Ильёй нет — про то молчим и
   ставим смежный факт; чего не заявляем, перечисляем честно В ОТЧЁТЕ ЕМУ, а не
   в письме работодателю.
7. **Страница формы отклика (write-эндпоинт из правила 0.1) не открывается.**
   Литерал адреса не пишется в код и в команды: PreToolUse-хук
   `~/.claude/hooks/block_vacancy_response.py` отклоняет вызов, в тексте
   которого этот путь есть. Отклонённую команду перестраивать, а не повторять.
   Снималось точечно и только прямым словом Ильи (136782983, 136582108).
8. **Сообщения работодателю не уходят в одностороннем порядке.** Готовый текст
   сначала Илье, дальше ждать. Касается и телеграм-ников, и почты из вакансий,
   найденных вне hh.
9. **Формат письма (п.9.1)**, ровно такой:
   - строка «<ФИО> - <роль дословно из вакансии>»;
   - 2–3 предложения контекста;
   - 4–6 буллетов вида «требование СЛОВАМИ ВАКАНСИИ - мой факт с числом»;
   - строка стека;
   - «Готов обсудить детали на встрече.»;
   - контакты одной строкой: «<ФИО>, <телефон>, <телеграм>».
     Реальные значения лежат в `agent/owner.local.md` (в `.gitignore`) и в
     репозиторий не попадают: он публичный.
   Между блоками пустая строка, до 1500 знаков (проверяет сама отправка),
   тире и многоточий нет — только дефис.
10. **Любое пересланное сообщение сверяется с `tg-bridge/tg_inbox.jsonl` ДО
    действия.** Системное уведомление о задаче согласием не является. Длинная
    пересылка приходит разбитой на части и не по порядку — собирать по
    `message_id`.

**Сопутствующее, из его же слов:**

- Текущее место работы — ОДНА должность за весь срок: название подгоняется
  под вакансию, компания и даты неизменны. Конкретика — в `owner.local.md`.
- Профильное резюме на hh (его id — в `owner.local.md`) не трогать.
- Роли «продуктовый аналитик» и рядовой «аффилейт-менеджер» не предлагать.
- Повтор запуска — только на ЖЁСТКОМ отказе (нет логина, файл не приложен).
- Кириллица в консоли битая (cp1251): диагностику писать файлом в UTF-8.

## 1. Авторизация

Перед любыми действиями с hh.ru проверь cookies:
```
hh auth status
```
Если нет — запусти `hh auth login`. Откроется браузер, пользователь логинится вручную.

Файл cookies: `hh_cookies.json` (в .gitignore, не коммитится).

## 2. Поиск вакансий

```
hh search --query "Python Developer" --salary 150000 --period 14 --max-pages 2
```

Флаги:
- `--json` — вывод в JSON для программной обработки
- `--headless` — без графического интерфейса (на сервере)

Поля результата: `vid`, `title`, `employer`, `salary`, `link`, `applied`.

## 3. Проверка статуса

Перед откликом **всегда** проверяй, не откликался ли уже:
```
hh verify <vid>
```

`hh verify` ходит только на read-only страницу `/vacancy/<vid>` — безопасно.
Массовая проверка: `hh negotiations --json` или скан чатов. НЕ полагайся на
`applied` из `hh search` (правило 0.4) и НЕ открывай `vacancy_response`
(правило 0.1).

## 4. Отклик с сопроводительным

**ВАЖНО**: сопроводительное отправляется вместе с откликом, а не после.

```
hh apply <vid> --letter cover_letter.txt [--headless]
```

После `hh apply` обязательно верифицируй письмо в чате работодателя
(правило 0.2) — возвращаемые флаги ненадёжны:
- Вакансия С вопросами: письмо доходит до чата, но readback часто даёт
  ложный отказ «Letter not persisted after submit».
- Вакансия БЕЗ вопросов: сохранение письма на карточке отклика НЕ доносит
  его до чата — чат остаётся «Без сопроводительного письма». Лечится
  отправкой письма сообщением в `hh.ru/chat/<chatId>`.

Формат сопроводительного:
- Приветствие, представление
- Почему эта вакансия и компания
- Ключевой опыт (2-3 предложения)
- Чем можешь быть полезен
- Подпись

## 5. Telegram

**Писать только в топики общей группы, не в личку бота.** Группа форумная:
без `message_thread_id` сообщение падает в общий поток, где Илья его не читает.
Топики: `hh` = 79 (HH.ru), `linkedin` = 101, `prep` = 106 (подготовка к
собесу), `reports` = 6. Имена лежат в `telegram.threads` конфига, топик по
умолчанию — `hh`.
```
hh tg send "Текст" --thread linkedin
```

**Второго слушателя не поднимать.** Очередь `getUpdates` у бота одна на два
проекта: второй слушатель отнимает сообщения у первого, и кто-то из двоих
немеет. Слушает сосед (cs2-betting, `tg_inbox.py follow`), мы читаем его базу
только на чтение:
```
py tg_topic_inbox.py            # новое с прошлого раза
py tg_topic_inbox.py --all      # вся история по топикам
```

Чтение входящих (от пользователя через Telegram):
```
hh tg inbox [--clear]
```

Проверка непрочитанных:
```
hh tg count
```

## 6. Проверка откликов / переговоры

```
hh negotiations [--json]
```

Показывает статус активных переговоров.

## 7. Порядок работы при запросе "найди и откликнись"

1. `hh search --json` — найти свежие вакансии
2. Для каждой проверить дубли через `hh verify <vid>` / `hh negotiations`
   (НЕ через флаг `applied` из поиска — он ненадёжен)
3. Показать пользователю список новых вакансий на утверждение и ЖДАТЬ ответа
4. После утверждения: откликаться ТОЛЬКО на явно названные пользователем
   вакансии — подготовить сопроводительные и `hh apply <vid> --letter ...`
5. Верифицировать письмо в чате по каждому отклику (правило 0.2)
6. Отправить финальный отчёт одним сообщением в Telegram

## 8. Cover Letter Generator

Пиши сопроводительные в стиле:
- Кратко и по делу
- Фокус на релевантном опыте (Product Manager, iGaming, Web3)
- Цифры и результаты где возможно
- Без лести и общих фраз

Структура:
- Тема / Заголовок вакансии
- Приветствие
- Кто я (1 предложение)
- Почему подхожу (2-3 предложения с фактами)
- Чем могу быть полезен (1 предложение)
- Подпись

## 9. CV Design Pipeline

Для генерации CV в PDF:
1. Брать HTML шаблон из `cv_designs/`
2. Заполнять данными кандидата
3. Открывать в Playwright (headless)
4. Экспортировать в PDF
5. Отправлять через Telegram

## 10. Telegram bridge

Долгоживущий процесс `tg_bot.py` слушает входящие сообщения
и пишет их в `tg_inbox.jsonl`. Агент читает этот файл командой `hh tg inbox`.

## 11. Безопасность

- `config.local.json` — в .gitignore (токены, прокси)
- `hh_cookies.json` / `linkedin_cookies.json` — в .gitignore (сессии)
- `tg_inbox.jsonl` — в .gitignore (переписка)
- `li_profile/` — в .gitignore (персистентный профиль Chrome для LinkedIn)
- В публичный репозиторий идёт только код без секретов
- При первом запуске: `hh setup` проверяет всё необходимое

## 12. LinkedIn (`li-tools/`)

Скрипты запускаются напрямую (не через `hh` CLI): `python li-tools/li_send_message.py <url> <msg_file> name=<ExpectedName>`.
Все используют персистентный профиль `li_profile/` (логин руками один раз,
дальше сессия сохраняется — как `hh_cookies.json` для hh.ru).

- `li_send_message.py <url> <msg_file> name=<Имя> [company] [dry]` — DM в первый контакт
- `li_compose_new.py <recipient_query> <expect_token> <msg_file> [dry]` — новый диалог
- `li_reply_thread.py <name_token> <msg_file> [attach=<path>] [dry]` — ответ в существующем треде
- `li_connect_note.py <profile_url> <expect_token> <msg_file> [dry]` — заявка на коннект с запиской
- `li_company_modal.py <company_url> <expect_company> <msg_file> [topic=<substr>] [dry]` — сообщение странице компании (лимит 750 знаков)
- `li_msg_audit.py <out_file> <name1> [name2 ...]` — дамп списка диалогов + истории тредов для сверки

Всегда сначала пробуй с флагом `dry` (заполняет, не отправляет) для новых
адресатов/сценариев. Ограничения LinkedIn: 2-я степень связи без Premium —
только InMail, не бесплатный DM; риск блокировки аккаунта за автоматизацию
осознанно принят пользователем.
