# Security Model

## Threat model

hh-agent хранит:
- **Telegram bot token** — полный доступ к боту
- **hh.ru session cookies** — доступ к аккаунту hh.ru от имени пользователя
- **Proxy credentials** — доступ к прокси
- **Переписка** — `tg_inbox.jsonl` может содержать личные сообщения

## Secrets protection

### .gitignore: белый список, а не чёрный

Репозиторий публичный, поэтому `.gitignore` закрывает корень целиком (`/*`)
и открывает поимённо только инструментарий и документацию. Новый разовый
скрипт, дамп вакансии, письмо или скриншот не утекут просто потому, что под
них никто не написал правило.

Чёрный список этого не давал. Аудит 03.09.2026 нашёл среди кандидатов на
коммит:

| Находка | Почему опасно | Почему проскочило |
|---|---|---|
| `data/login_profile/` (48 МБ, 509 файлов) | живой профиль Chrome: cookies сессии hh.ru и apikey в кеше = доступ к аккаунту | правила на `data/` не было вовсе |
| `hh_cookies.json.bak` | те же cookies, копия | не подходил ни под `hh_cookies.json`, ни под `*_cookies.json` |
| ~1300 файлов откликов | ФИО, телефон, почта, а также контакты рекрутеров и работодателей | под шаблоны не попадали |

Всегда закрыты, где бы ни лежали:

| Файл | Содержимое |
|---|---|
| `config.local.json` | Telegram token, прокси, chat_id |
| `*_cookies.json`, `*.bak` | cookies сессии hh.ru |
| `data/`, `*_profile/`, `**/login_profile/` | профили браузера = живые сессии |
| `tg_inbox.jsonl` | переписка в Telegram |
| `agent/owner.local.md`, `*.local.md` | ФИО, телефон, телеграм, id резюме |
| `cover_letters/`, `ats_html/`, `answers/`, `*.pdf`, `*.png` | готовые отклики и скриншоты с личными данными |

### Config separation

```
config/
  config.example.json    ← в репозитории (шаблон с плейсхолдерами)
config.local.json       ← только локально (в .gitignore)
```

### Cookie permissions

hh.ru cookies авторизуют действия от имени пользователя.
- Хранятся только локально
- Не передаются третьим лицам
- Истекают через ~30 дней

## First-run permission setup

При первом запуске через Claude Code:
1. `hh setup` проверяет конфигурацию
2. Пользователю предлагается подтвердить права: Bash (python/playwright), Read (конфиги), Write (файлы)
3. Всё прозрачно — никаких скрытых операций

## Recommendations

### Перед публикацией

Проверять надо ровно тот набор, который уйдёт в коммит: отслеживаемое плюс
новое неотслеживаемое. Проверять рабочий каталог целиком бесполезно, а
проверять только отслеживаемое поздно - новый секрет приходит с новым файлом.

```bash
# доступы и личные данные в наборе к публикации
py tools/audit_pii.py --out audit.txt \
   --phone '+7 900 000-11-22' --email me@example.com --name Иванов

# что именно попадёт в коммит
git status --porcelain
git diff --cached --stat
```

Ненулевой код возврата у `audit_pii.py` означает найденные доступы -
публиковать нельзя. Раздел «личные данные» смотрится глазами: имя автора в
`LICENSE` законно, телефон в примере кода - нет.

Тот же контур автоматически: `gitleaks` стоит и в `.pre-commit-config.yaml`
(блокирует коммит), и в CI на каждый push с `fetch-depth: 0`, то есть по всей
истории, а не только по последнему коммиту.

Если секрет всё-таки попал в историю, `.gitignore` его оттуда не уберёт:
нужно переписать историю (`git filter-repo --path <файл> --invert-paths`,
затем force-push) **и обязательно отозвать сам секрет** - токен и cookies
считаются скомпрометированными с момента публикации, даже если коммит уже
удалён: копии остаются в форках, кешах и зеркалах.

### GPG signing

```bash
# Настройка подписи коммитов
git config --global user.signingkey YOUR_KEY
git config --global commit.gpgsign true
```

### Environment variables (альтернатива)

Вместо `config.local.json` можно использовать переменные окружения:

```bash
export HH_TG_TOKEN="..."
export HH_CHAT_ID="..."
export HH_PROXY="..."
```

## Known limitations

- Cookies хранятся в открытом виде — не используй на общих компьютерах
- Playwright запускает полноценный браузер — временные файлы остаются на диске
- Telegram Bot API использует HTTPS, но метаданные (кто кому пишет) видны Telegram
